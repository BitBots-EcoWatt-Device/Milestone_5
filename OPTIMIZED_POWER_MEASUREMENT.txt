🔍 ROOT CAUSE ANALYSIS:

The Light Sleep implementation is PARTIALLY working but NOT optimally because:

1. **Light Sleep is NOT being triggered during main delays**
   - Light Sleep only works when WiFi stack detects idle time
   - Our delay(100) calls are NOT entering light sleep properly
   - ESP8266 Light Sleep requires WiFi modem to be active

2. **LIGHT_SLEEP_T only affects WiFi modem, not CPU**
   - wifi_set_sleep_type(LIGHT_SLEEP_T) puts WiFi modem in light sleep
   - It does NOT put the CPU to sleep between operations
   - CPU still runs at full speed during delay() calls

3. **Missing Deep Sleep or Timed Light Sleep**
   - We need to use WiFi.forceSleepBegin() for deeper savings
   - Or use wifi_fpm_do_sleep() for forced sleep periods
   - Current implementation relies on automatic WiFi modem sleep only

4. **High operation frequency**
   - 120 sensor polls in 10 minutes = 1 poll every 5 seconds
   - Device spends most time actively polling, not waiting
   - Not enough idle time for sleep to be effective

================================================================================
RECOMMENDED NEXT STEPS FOR BETTER OPTIMIZATION
================================================================================

OPTION 1: Implement Forced WiFi Sleep (Recommended)
──────────────────────────────────────────────────
Add this between polling/upload cycles:

```cpp
// After sensor poll, before next poll
WiFi.forceSleepBegin();  // Force WiFi off
delay(4000);              // Sleep for 4 seconds
WiFi.forceSleepWake();    // Wake WiFi up
delay(100);               // Give WiFi time to reconnect
```

Expected Improvement: 40-50% power reduction
Expected Average Current: ~45-50 mA

OPTION 2: Use Timer-Based Deep Sleep (Maximum Savings)
────────────────────────────────────────────────────────
Replace main loop with:

```cpp
// Poll sensors
// Upload data
// Then deep sleep
ESP.deepSleep(30e6); // Sleep 30 seconds
// Device auto-restarts after sleep
```

Expected Improvement: 70-80% power reduction
Expected Average Current: ~20-25 mA
⚠️ WARNING: Device restarts after each wake, loses variables

OPTION 3: Dynamic Clock Scaling (Additional 10-15%)
──────────────────────────────────────────────────
Add frequency switching:

```cpp
system_update_cpu_freq(80);  // Slow down to 80MHz
// Do non-critical work
system_update_cpu_freq(160); // Speed up for WiFi
```

Expected Additional Improvement: 10-15%
Can combine with Option 1 for total ~55% savings

OPTION 4: Increase Polling Interval (Easiest)
───────────────────────────────────────────────
Change polling from every 5 seconds to every 30 seconds:
- More time in sleep mode
- Less frequent active processing
- Expected Improvement: 30-40% additional savings

================================================================================
WHY LIGHT SLEEP ALONE IS NOT ENOUGH
================================================================================

ESP8266 Light Sleep Limitations:
1. Only puts WiFi modem to sleep, CPU stays active
2. Requires WiFi to be connected and idle
3. Automatic sleep is opportunistic (not guaranteed)
4. Delay() does not trigger light sleep reliably
5. Best for scenarios with long idle periods between WiFi activity

Our Use Case:
- Device polls every 5 seconds (very frequent)
- 80% of time spent actively processing
- Little time for automatic WiFi sleep to engage
- Need FORCED sleep or DEEP sleep for better savings
